# End-to-End Encrypted Chat Application

This project is a fully functional command-line based end-to-end encrypted (E2EE) chat application built with Python. It uses a client-server architecture and RSA cryptography to ensure that messages are secure and can only be read by the intended recipient.

## Features

-   **End-to-End Encryption**: Messages are encrypted on the client-side and can only be decrypted by the recipient's client. The server never sees the unencrypted content.
-   **User Registration & Login**: Users can create accounts and log in securely. Passwords are hashed before being stored.
-   **Real-time Chat**: Online users receive messages instantly.
-   **Persistent Chat History**: All messages are stored, and users can view their chat history upon logging in.
-   **Secure Key Management**: RSA private keys are generated and stored locally on the client's machine and are never sent to the server.

## File Structure

The project is organized into several key files:

-   `server.py`: The main application for the chat server.
-   `client.py`: The main application for the chat client.
-   `crypto.py`: Contains all functions for RSA key generation, encryption, and decryption.
-   `storage.py`: Handles data persistence, storing user info and messages in JSON files.
-   `requirements.txt`: Lists the necessary Python packages.
-   `users.json`: A file created by the server to store user data (username, hashed password, public key).
-   `messages.json`: A file created by the server to store encrypted chat messages.
-   `{username}_private_key.pem`: Private key files generated by the client for each registered user.

## Prerequisites

-   Python 3.6+
-   pip (Python package installer)

## Setup and Installation

1.  **Clone the repository or download the source code.**

2.  **Navigate to the project directory:**
    ```bash
    cd path/to/chat-application
    ```

3.  **Install the required dependencies:**
    ```bash
    pip install -r requirements.txt
    ```

## How to Run the Application

You will need two or more terminal windows to run the server and the clients.

### 1. Start the Server

In your first terminal, run the following command to start the server:

```bash
python3 server.py
```

You should see the output `[LISTENING] Server is listening on 127.0.0.1:65432`. The server is now ready to accept client connections.

### 2. Run the Client(s)

For each user you want to have in the chat, you need to open a new terminal.

#### Step-by-Step Usage

**Terminal A - User "Alice"**

1.  **Launch the client:**
    ```bash
    python3 client.py
    ```

2.  **Register a new user:**
    -   At the prompt, enter `1` to Register.
    -   Enter a username (e.g., `alice`).
    -   Enter a secure password.
    -   A private key file named `alice_private_key.pem` will be created in the directory.

3.  **Log in:**
    -   Enter `2` to Login.
    -   Enter the username and password you just created.
    -   You are now in the main menu.

**Terminal B - User "Bob"**

1.  **Launch another client instance in a new terminal:**
    ```bash
    python3 client.py
    ```

2.  **Register a second user** (e.g., `bob`) following the same steps as above. A new `bob_private_key.pem` file will be created.

3.  **Log in as Bob.**

### 3. Start Chatting

1.  **From Alice's terminal:**
    -   Choose option `1` to `List Users`. You should see `alice` and `bob`.
    -   Choose option `2` to `Send Message`.
    -   Enter `bob` as the recipient and type your message.

2.  **In Bob's terminal:**
    -   The message from Alice will appear in real-time.
    -   Bob can now reply by following the same steps to send a message to `alice`.

3.  **View History:**
    -   Either user can log out and log back in.
    -   Choose option `3` to `Show History` to see the entire conversation, securely decrypted on the client-side.

## Security Model

This application implements End-to-End Encryption (E2EE).
- The server acts only as a relay and storage for encrypted data. It cannot read the messages.
- Your private key is stored locally on your machine and is essential for decrypting messages. **Do not share your `_private_key.pem` file.**
